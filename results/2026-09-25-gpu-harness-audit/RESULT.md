# GPU measurement harness audit after a failed paid run

The latest real paired-host run qualified six local and six remote requests, then an agent code error stopped calibration after its first three-request episode. The runner read `engine-load.json` through a helper that accepts only objects, but the client writes an array. That mismatch was fixed and tested against the exact saved53-sample file. No new GPU rental occurred during this audit.

A deeper review found a second, previously silent measurement defect. The pinned inference-perf v0.6.1 image creates request and streaming times with Python `time.perf_counter()` (`/workspace/inference_perf/loadgen/load_generator.py`, `/workspace/inference_perf/apis/streaming_parser.py`). The load observer used `time.time()`. In the saved trial, request times were around1922seconds while load samples were around1790299445Unix seconds, so **both foreground load timelines were empty**. The earlier offline report incorrectly called those entries validated. Its routes and transfer counters were valid; its load-to-request alignment was not. The client now records the performance clock with each load sample. The reader aligns on that clock and fails any foreground request lacking nearby valid load observations. Isolated metrics timeouts remain visible but do not fail a trial if valid samples still cover the requests. The saved old trial cannot be repaired into honest aligned load data.

Validation: **286 tests run;283 passed on macOS,3 unchanged Linux-only tests skipped**. A targeted test reads the saved real array and rejects its clock mismatch; another checks the client's actual observer emits performance-clock samples. A full local replay used the existing40 completed native inference-perf synthetic trials through the production runner's `gpu_checks=True` branch, including route/transfer checks, load timelines, calibration, queue pressure screen, tuning,24 policy selections and a complete24-cell report. It used constructed GPU counters and load observations, so it verifies data handling and control flow, **not GPU performance or an allowance benefit**. No cloud resources started. The 1.2GiB private synthetic fixture stays in local run state; the checked-in replay script accepts its path as an argument.

Limits: this replay does not reproduce live GPU telemetry, model behavior, cloud interruptions or the exact timing of a future concurrent run. The real first episode's transfer evidence is retained; full balanced calibration and held-out policy comparison have not happened. Another paid run is not authorized and the remaining pool cannot admit the full protocol as configured.
